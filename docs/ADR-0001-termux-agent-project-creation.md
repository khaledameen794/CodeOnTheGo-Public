# ADR-0001: نواة إنشاء مشروع عبر الوكيل داخل جذر مشاريع التطبيق

**الحالة:** مقبول للتنفيذ المرحلي
**التاريخ:** 24 أغسطس 2026
**القرار:** إنشاء نواة مستقلة قابلة لاختبار JVM، ثم تكييفها داخل التطبيق لاستعمال
قوالب المشروع ومسار فتح Termux الرسميين.

## السياق والأدلة

الجذر الافتراضي الفعلي في التطبيق هو `Environment.PROJECTS_DIR`، ويهيئه
`Environment.init` إلى مجلد `CodeOnTheGoProjects` على التخزين المشترك؛ ليس مسار
`ApplicationAndroid` داخل home في Termux:

```kotlin
File(FileUtil.getExternalStorageDir(), Environment.PROJECTS_FOLDER)
    .resolve("<safe-project-name>")
```

يمكن للمستخدم تغيير حقل موقع الحفظ في نموذج القالب. يعرض حوار الموافقة المسار
canonical الناتج قبل الإنشاء. لا يقبل المنسق جذرًا من طلب النموذج اللغوي.

يوفر التطبيق بالفعل `ProjectCreationManager` الذي يتحقق من قيود معلمات القالب ثم
ينفذ وصفته خارج خيط الواجهة ويعيد `RecentProject` عند النجاح. وتفتح واجهة
القوالب مشروعاً جديداً من خلال `MainActivity.openProject` بعد اكتمال الوصفة.
وتعتمد نقطة فتح Termux الرسمية على مشروع مسجل في `IProjectManager` كي تمرر مجلد
العمل إلى `TerminalActivity`. [1] [2] [3]

> مخرجات النموذج اللغوي غير موثوقة. لا يمكن أن تصبح اسم ملف أو مساراً أو أمراً
> قابلاً للتنفيذ إلا بعد تحقق محلي حتمي ومستقل عن النموذج.

## القرار

### 1. ملكية الوحدات واتجاه التبعيات

تضاف وحدة جديدة باسم مبدئي `agent-project-core`. لا تعتمد هذه الوحدة على Android
أو Termux أو واجهة التطبيق أو مزود LLM. تملك فقط القرار الحتمي: التحقق من اسم
المشروع، اشتقاق مساره المباشر، كشف التعارض، حالات العملية، ومتطلبات الموافقة.

يبقى التكييف مع Android في طبقة التطبيق أو في وحدة ربط لاحقة. هو وحده الذي
يعرف الجذر الافتراضي لـ Termux، كتالوج القوالب، `ProjectCreationManager`،
و`MainActivity.openProject`. لا تستدعي النواة `TerminalActivity` مباشرة ولا
تستقبل `Context` أو `Intent`.

```text
دردشة / LLM (غير موثوق)
        │ AgentProjectCreationRequest
        ▼
agent-project-core
  ├── ProjectNamePolicy
  ├── TermuxProjectPathPolicy
  ├── CreationPlan / ApprovalState
  └── ProjectCreationCoordinator (واجهة مجردة)
        ▼
Android adapter
  ├── template parameter mapper
  ├── ProjectCreationManager
  ├── MainActivity.openProject
  └── TerminalSidebarAction بعد تسجيل المشروع
```

### 2. عقد الإدخال واسم المشروع

تقبل النواة طلباً منظماً فقط، وليس نص shell أو مساراً كاملاً:

```kotlin
data class AgentProjectCreationRequest(
    val projectName: String,
    val templateToken: String,
    val packageName: String?,
    val language: String?,
)
```

تقبل السياسة اسماً من 1 إلى 64 محرفاً يبدأ بحرف Unicode، ثم يسمح بالحروف
والأرقام والمسافة الداخلية و`_` و`-`:

```text
^[\p{L}][\p{L}\p{N} _-]{0,63}$
```

هذا القناع يحدد المحارف المسموحة، لكنه لا يفرض وحده شرط المسافة الداخلية؛
فالتحقق يرفض أولاً أي قيمة لا تساوي `trim()`، ثم يطابقها مع القناع. لذلك
المسافات مسموحة داخل الاسم فقط، ولا تُقبل في بدايته أو نهايته.

ترفض النواة الاسم الفارغ، والمسافات الطرفية، والبداية غير الحرفية، و`..`،
والواصلات `/` و`\\`، والمسارات المطلقة، ومحارف التحكم. لا تُطبّق النواة
تطبيعاً صامتاً؛ الاسم الذي يراجعه المستخدم هو نفسه الذي يُشتق منه مجلد المشروع.

### 2.1 اختيار القالب

معرفات `Template.templateId` الحالية تُنشأ عشوائياً عند تحميل القوالب، لذلك ليست
معرفاً ثابتاً يصلح للنموذج أو للتخزين طويل الأجل. يعرض التطبيق قائمة قوالب
مسموحة من `ITemplateProvider` ويصدر لكل عنصر `templateToken` محدوداً بعمر جلسة
الاختيار. يختار المستخدم أو الوكيل قيمة من هذه القائمة فقط، ثم يحل المكيّف الرمز
إلى القالب من المزود ويعيد التحقق منه قبل التنفيذ. يرفض الرمز الفارغ أو المنتهي
أو غير المعروف، ولا ينفذ وصفة من اسم أو مسار يقترحه النموذج.

### 3. سياسة المسار والتعارض

لا يقدم النموذج الجذر ولا أي جزء مسار إضافي. يمرر التطبيق إلى النواة الجذر
الافتراضي من `Environment.PROJECTS_DIR` أو المسار الذي أدخله المستخدم في نموذج
القالب. يظهر المسار canonical كاملاً في حوار الموافقة. تنشئ النواة الهدف حصراً
بصيغة `root / safeProjectName`، بعد تطبيع الجذر والتحقق من أن هدفه المباشر يقع
داخله.

لا يكفي فحص نص يبدأ بـ root. يفحص المكيّف الجذر canonical، ويرفض أي اسم غير
آمن، ثم يتحقق قبل الكتابة من أن الهدف غير موجود ولا يوجد رابط رمزي أو عنصر
متعارض في نقطة الهدف. تفشل العملية بـ `PathRejected` أو `ProjectAlreadyExists`
بدلاً من الاستبدال أو الدمج الصامت. تتبع هذه السياسة مبدأ منع عبور المسارات
المطبق في إرشادات المشروع. [4]

يحجز منفذ وصفة القالب المجلد الهدف حصرياً عبر `Files.createDirectory` قبل كتابة
أي ملف. ولذلك فإن ظهور مجلد الاسم نفسه بين الخطة والتنفيذ يفشل بصورة صريحة ولا
يمكن لوصفتين متزامنتين اعتبار المشروع نفسه ناجحاً. هذا يشدد سلوك القوالب العامة
بصورة مقصودة: حتى المجلد الموجود والفارغ لم يعد نجاحاً صامتاً؛ لا توجد هجرة
بيانات لازمة لأن الوصفة لم تكن تملك ذلك المجلد بعد.

### 4. الموافقة وحالة العملية

تعمل العملية بالحالات التالية:

```text
Draft → Planned → AwaitingApproval → Creating → Created
                         │                 ├→ Failed
                         └→ Rejected        └→ Cancelled
```

ينشئ المخطط (`CreationPlan`) قيمة غير قابلة للتغيير تتضمن الاسم المقبول والمسار
المشتق ورمز القالب ومعلمات الحزمة واللغة. تعرض الواجهة القالب والاسم والمسار
والحزمة واللغة للمراجعة. لا يستدعي المكيّف `ProjectCreationManager.execute` قبل
موافقة صريحة تربط بالخطة نفسها؛ إلغاء الحوار لا يستدعي بوابة الإنشاء.
وتسجل النواة سبب الرفض أو الفشل من دون محتوى ملفات أو مفاتيح أو أسرار.

### 5. التكامل الرسمي مع القوالب وTermux

يحوّل المكيّف فقط المعلمات المعتمدة في `CreationPlan` إلى معلمات القالب القائم.
يستعمل بعد ذلك `ProjectCreationManager` بدلاً من استدعاء
`TemplateRecipeExecutor` مباشرة. بعد نجاح الوصفة، يستدعي التدفق القائم
`MainActivity.openProject` لتسجيل المشروع وفتحه. لا يبدأ جلسة Termux إلا بعد أن
تكون حالة المشروع المنشور في `IProjectManager` جاهزة؛ عندئذ يستعمل عقد
`TerminalSidebarAction.startTerminalActivity` الموجود بدلاً من بناء Intent
موازٍ. [1] [2] [3]

يربط `TemplateListFragment` اختيار المستخدم بكتالوج معزول قصير العمر، ويتحقق من
تطابق ترتيب البطاقات وأسمائها مع خيارات الجلسة قبل إصدار الرمز. يعيد المصنع
قراءة أرشيف القالب عند استهلاك الرمز، ثم ينسخ القيم التي راجعها المستخدم إلى
المثيل الجديد ويتحقق من تطابق الاسم والمسار والحزمة واللغة قبل استدعاء المدير.

#### شرط العزل قبل مكيّف Android

`ITemplateProvider` يخزن كائنات `Template` قابلة للتغيير في ذاكرة مؤقتة. لذلك
لا يغيّر المكيّف معلمات ذلك الكائن. ينفذ `ArchiveTemplateSessionFactory`
`IsolatedTemplateSessionFactory` ويعيد قراءة الأرشيف الموثوق بعد استهلاك رمز
عشوائي قصير العمر وأحادي الاستعمال من `TemplateSessionRegistry`. ينسخ المكيّف
المعلمات المطابقة إلى النسخة الجديدة فقط، ويتحقق من نوعها وترتيبها وقيمها قبل
التنفيذ. إذا تغير الأرشيف أو انتهت الجلسة، يرفض الإنشاء قبل الكتابة.

### 6. الصلاحيات وحدود الإصدار

صلاحية الإصدار الأول هي **إنشاء مشروع جديد من قالب معروف داخل جذر المستخدم الذي
راجعه**.
لا تمنح عملية الإنشاء قراءة عامة للملفات، أو تعديل مشروع قائم، أو shell، أو
Gradle، أو Git، أو حذف الملفات. اتصالات مزود AI منفصلة: لا تحدث إلا عند طلب
شبكي صريح، وبالبيانات الموضحة في إعدادات المزودين. بقية القدرات مراحل لاحقة
وتبقى خاضعة لتصنيف التأثير والموافقة المنفصلة في تصميم الوكيل العام. [5]

## خطة الاختبار المطلوبة قبل الدمج

| الطبقة | الاختبارات |
| --- | --- |
| `ProjectNamePolicy` | اسم ASCII وعربي؛ الفراغ والمسافات الطرفية؛ `..`؛ شرطة مائلة؛ شرطة عكسية؛ مسار مطلق؛ بداية رقمية؛ تجاوز 64 محرفاً؛ محارف تحكم |
| `TermuxProjectPathPolicy` | أن الهدف ابن مباشر للجذر؛ رفض الجذر غير الصالح؛ رفض التعارض؛ عدم قبول رابط رمزي أو استبدال موجود |
| منسق الحالة | لا تنفيذ قبل الموافقة؛ الرفض أو الإلغاء لا يكتبان؛ التكرار والتعارض والمسار غير المتوقع يفشلون بصورة صريحة |
| مصنع الجلسة | إعادة فتح أرشيف جديد؛ رمز منتهي/مستهلك؛ تغيّر بصمة الأرشيف؛ فصل المثيل المعزول عن القالب المرئي |
| مكيّف Android | تأكيد شاشة القالب؛ مطابقة المعلمات؛ لا تنفيذ قبل التأكيد؛ فتح المشروع فقط بعد نجاح المسار المخطط |

## النتائج والحدود

يمنع هذا القرار أن يتحول طلب محادثة إلى وصول كامل لملفات الهاتف أو إلى shell
عام. يتصل زر إنشاء القالب حاليًا بالمنسق ويعرض الموافقة محليًا. موائمات Gemini
وDeepSeek تتبع واجهات API الرسمية وتدعم قائمة النماذج وطلب prompt نصي مفرد؛ لا
ترسل ملفات المشروع أو سجل المحادثة تلقائيًا، ولا تنفذ tool calls. تحذر Google
من تضمين مفاتيح API واسعة الصلاحية في تطبيق هاتف إنتاجي وتوصي بوسيط خلفي؛ لذلك
يظهر هذا القيد في الإعدادات، مع تشفير محلي لا يدعي حماية مفتاح مكشوف من تطبيق أو
جهاز مخترق. [6] [7] لا توجد بعد واجهة محادثة تربط رد النموذج بخطة الإنشاء؛ هذا
عمل لاحق منفصل.
